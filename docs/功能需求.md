# 仿蓝桥杯学生程序判题系统：功能需求

> 这份文档回答一个具体问题：**做一个“像蓝桥杯那样判学生程序对错”的系统，需要哪些功能？**
>
> 每一项都标了优先级：
>
> - **P0 必须**：没有它就无法完成一次可信的判题；
> - **P1 应该**：让系统真正好用、能组织一场测验；
> - **P2 可选**：面向比赛平台/规模化运营。
>
> 文末附有本仓库（`bluebridge-judge`）的实现对照表。

---

## 一、先看蓝桥杯的赛制，它决定了系统形态

蓝桥杯（大学组）的判题与普通在线 OJ 有明显区别，功能设计必须围绕这些差异：

| 蓝桥杯规则 | 对判题系统的要求 |
| --- | --- |
| 赛后统一评测，比赛过程中没有实时反馈（OI 赛制） | 支持“批量收题 → 统一判题 → 出成绩”，而不是必须实时排队 |
| 题型分两类：结果填空、程序设计 | 结果填空只需比对答案；程序设计按测试点运行判分 |
| 按测试点给分，有部分分 | 每个测试点独立计分，不能“错一个点整题 0 分” |
| 编译环境固定（C++17、Java、Python 等） | 统一编译参数、统一运行方式，避免“本地能过、评测不过” |
| 学生代码在评测机上运行 | 必须有资源限制和基本的隔离，不能让一份死循环拖垮整场评测 |
| 测试数据不公开 | 运行学生程序时不能让它读到标准答案 |

因此，一个最小可用的系统 = **题库 + 测试数据 + 提交清单 + 编译 + 受限运行 + 输出比对 + 按点计分 + 成绩报告**。

---

## 二、角色与使用场景

| 角色 | 关心什么 | 典型操作 |
| --- | --- | --- |
| 教师 / 教练 | 题出得对不对、学生得多少分、错在哪 | 建题、导入测试数据、收作业、一键判题、看报告、重测 |
| 学生 | 我错在哪、为什么只有部分分 | 提交源码/答案、看成绩单和测试点详情 |
| 系统管理员 | 评测稳不稳、数据安不安全 | 装编译环境、配置沙箱、备份题库、查日志 |

典型场景：

1. **课堂小测**：30 名学生、3 道题，课后收齐 `.cpp` 文件，老师批量判题，第二天发成绩单。
2. **校内选拔**：上百人、多场次、排行榜、封榜、申诉重测。
3. **公网 OJ**：随时提交、实时反馈、强沙箱、防作弊——这是 P2 的目标。

## 三、功能清单

### 3.1 题库与题目管理

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| Q1 | 两种题型 | P0 | `program` 编程题、`fill_result` 结果填空 |
| Q2 | 题面 / 标准答案 | P0 | 题面给人和网页看；答案用于比对 |
| Q3 | 时限、内存、总分 | P0 | 每题独立配置；不同语言可加补偿 |
| Q4 | 测试点及分值 | P0 | 每个测试点可单独给分；不写分值则平均分配 |
| Q5 | 题目完整性校验 | P0 | 缺测试文件、缺标准答案、分值对不上时直接报错，不能静默 0 分 |
| Q6 | 题目复制 / 导入导出 | P1 | 换场次、改数据时不用重写 JSON |
| Q7 | 标签、难度、知识点 | P2 | 题库变大后按知识点组卷、做统计 |
| Q8 | 题目版本管理 | P2 | 修改题面/数据后仍能复现旧场次的判题结果 |

**关键细节**：结果填空题需要支持“多个可接受答案”（例如 `5050` 和 `5,050` 都算对）；编程题的测试点分值之和要与题目满分一致，系统应校验并提示。

### 3.2 测试数据管理

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| D1 | 输入 / 输出文件 | P0 | 按测试点组织，支持空输入 |
| D2 | 样例数据 | P0 | 题面展示用；可复用为第一个测试点 |
| D3 | 批量导入 / 导出（zip） | P1 | 从其他 OJ 迁移，或把题包发给别的老师 |
| D4 | 数据校验 | P1 | 检查空文件、编码、行末空白、答案是否为程序输出 |
| D5 | 数据保密 | P1 | 学生程序运行时不能读到答案文件；公网场景应加密存储 |
| D6 | 数据生成器 / 对拍 | P2 | 出题人自测，避免“错题” |
| D7 | 大测试数据 | P1 | 支持几十 MB 的输入，不能一次性读进内存 |

### 3.3 提交管理

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| S1 | 学生名单（姓名/学号/班级） | P0 | 成绩单按人聚合；支持只判某个学生 |
| S2 | 源码/答案文件提交 | P0 | 按扩展名识别 C++/C/Java/Python；也可显式指定 |
| S3 | 编码兼容 | P0 | Windows 学生常用 GBK，系统要自动识别并转 UTF-8，否则中文注释会编译失败 |
| S4 | 缺交、补交、重测 | P1 | 缺交要能标记；重测要能只跑某几个人 |
| S5 | 多次提交取最高分 | P1 | 蓝桥杯式练习中常见“允许重交” |
| S6 | 在线提交入口 | P2 | Web 上传 / 粘贴代码，实时返回结果 |

### 3.4 编译

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| C1 | 多语言支持 | P0 | C++17、C11、Java、Python 3；语言可扩展 |
| C2 | 固定编译参数 | P0 | 例如 `g++ -O2 -std=c++17 -DONLINE_JUDGE`，保证公平 |
| C3 | 编译错误原文 | P0 | 保留行号、列号、错误原因；报告中可展开 |
| C4 | 编译时限/内存 | P1 | 防止极端模板把编译器拖死 |
| C5 | 编译缓存 | P2 | 同一份代码重测时跳过编译，提高批量效率 |

**关键细节**：编译错误信息里不能只显示临时目录路径；要能定位到“第几行、什么错误”。Java 需要处理“文件名必须与 public 类名一致”的规则。

### 3.5 运行与资源限制（核心）

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| R1 | 每个测试点独立进程、独立工作目录 | P0 | 防止一个测试点写文件/改变量影响下一个 |
| R2 | 时间限制 | P0 | 墙钟时间；超时后强制结束 |
| R3 | 内存限制 | P0 | 记录峰值内存；超限判 MLE |
| R4 | 输出大小限制 | P0 | 防止 `while(1) cout<<...` 把磁盘写满 |
| R5 | 进程树清理 | P0 | 学生程序可能 fork/开子进程，超时后要全部杀掉 |
| R6 | 崩溃处理 | P0 | 空指针、除零、未捕获异常要稳定判 RE，不能被系统弹窗卡住 |
| R7 | 禁止再开子进程 | P1 | 防止提交里藏 `system()`、启动外部程序 |
| R8 | 文件系统隔离 | P1 | 只读、只暴露必要目录，禁止读标准答案和其他学生代码 |
| R9 | 网络隔离 | P1 | 禁止提交访问外网（公网 OJ 必须） |
| R10 | CPU 时间统计 | P1 | 与墙钟时间一起展示，便于分析“卡在 IO 还是计算” |
| R11 | 语言开销补偿 | P1 | Java/Python 启动慢，时限和内存要给固定补偿，否则对它们不公平 |

**关键细节**：Windows 上学生程序崩溃时可能弹出“程序已停止工作”对话框，导致评测线程一直等；必须关闭系统的错误对话框。Linux 上则要用 cgroup/namespace/seccomp 做真正的隔离。

### 3.6 输出比对

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| V1 | 忽略行末空格与文末空行 | P0 | 最常见、也最容易被误判的差异 |
| V2 | 按 token 比对 | P0 | 忽略所有空白差异，适合数值型题目 |
| V3 | 精确比对 | P1 | 字符串/格式题 |
| V4 | 浮点数误差 | P1 | `abs/rel ≤ 1e-6` 之类的容差 |
| V5 | 特殊评测（checker） | P1 | 答案不唯一（多解、构造题）时用脚本判断 |
| V6 | 多答案 | P1 | 结果填空题的多个可接受答案 |
| V7 | 错误定位 | P1 | 告诉学生“第 3 个数据/第 2 行不一致，期望 X，实际 Y” |

**关键细节**：比对前要统一换行符（CRLF/LF）；学生输出可能是 GBK，答案通常是 UTF-8，要先解码再比。

### 3.7 评分

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| G1 | 测试点独立计分 | P0 | 通过一个点拿一个点的分 |
| G2 | 部分分 | P0 | 蓝桥杯的核心特征 |
| G3 | 子任务（一组点全过才得分） | P2 | 部分 OI 题需要；蓝桥杯以测试点计分为主 |
| G4 | 总分 / 满分 / 通过率 | P0 | 个人、题目、班级三个维度 |
| G5 | 重测与成绩修正 | P1 | 错题、数据修正后只重跑受影响的人 |

### 3.8 评测结果

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| O1 | 标准状态机 | P0 | AC / WA / TLE / MLE / RE / CE / OLE / SE |
| O2 | 每个测试点详情 | P0 | 状态、得分、用时、内存、错误信息 |
| O3 | 编译输出 | P0 | CE 时保留完整编译器信息 |
| O4 | 结果持久化 | P0 | JSON/CSV，便于二次统计和申诉 |
| O5 | 重测 | P1 | 单份/整场重测 |
| O6 | 审计日志 | P2 | 谁在什么时候改了什么、重测了几次 |

状态定义：

| 状态 | 含义 |
| --- | --- |
| AC | 通过（Accepted） |
| WA | 输出与标准答案不一致（Wrong Answer） |
| TLE | 超过时间限制（Time Limit Exceeded） |
| MLE | 超过内存限制（Memory Limit Exceeded） |
| RE | 运行时错误：崩溃、非零退出、异常（Runtime Error） |
| CE | 编译错误（Compile Error） |
| OLE | 输出超过限制（Output Limit Exceeded） |
| SE | 判题系统自身错误（System Error） |

## 四、两种题型的具体判题流程

### 4.1 程序设计题

```text
读取源码 → 识别语言 → 按固定参数编译
  → 编译失败：CE，结束
  → 编译成功：
       for 每个测试点：
           新建工作目录 → 复制输入 → 限制时间/内存运行
           → 超时 TLE / 超内存 MLE / 非零退出 RE / 输出过大 OLE
           → 正常退出：比对输出 → AC 或 WA
           累加该测试点得分
  → 汇总总分，生成报告
```

### 4.2 结果填空题

```text
读取学生答案文本 → 去首尾空白 / 统一换行
  → 与一个或多个标准答案比较（可选忽略大小写）
  → 命中：AC，得满分；否则 WA，0 分
```

> 代码补全题不在此系统范围内；只保留结果填空题和程序设计题。

## 五、安全设计（最容易被低估的部分）

学生代码是**不可信代码**。判题系统必须在“能跑对”和“不能搞破坏”之间取得平衡。

### 5.1 需要防什么

| 风险 | 例子 | 对策 |
| --- | --- | --- |
| 死循环 / 死锁 | `while(1);` | 墙钟超时 + 强制杀进程树 |
| 内存炸弹 | 不停 `new` 大数组 | 内存上限 + 峰值统计 |
| 输出炸弹 | 无限打印 | 输出上限 + 超限终止 |
| 读标准答案 | `ifstream("answer.txt")` | 工作目录隔离、答案不落到运行目录、权限控制 |
| 开子进程 | `system("...")` | 限制活动进程数 / PID namespace |
| 联网 | 提交里发请求 | 网络 namespace / 防火墙 |
| 写坏系统 | 删除文件、改注册表 | 低权限用户 + 只读挂载 |
| 卡住评测 | 崩溃弹窗、等待输入 | 关闭错误对话框、stdin 重定向到文件/空设备 |
| 编译器攻击 | 恶意模板/宏 | 编译也在沙箱里跑，限制资源 |

### 5.2 Windows 本地模式的边界

Windows 没有 Linux cgroup/namespace 那样成熟的轻量隔离。作业对象（Job Object）能提供：

- 进程提交内存上限；
- 活动进程数限制；
- 超时后 `TerminateJobObject` 杀掉整棵进程树；
- 关闭作业句柄时兜底清理。

但它**不能**限制文件系统访问和网络。因此：

- 适合：课堂、校内、学生可信、老师自己的机器；
- 不适合：公网接收陌生代码。

### 5.3 生产环境建议

- Linux + cgroup v2 限制内存/CPU，PID namespace 隔离进程，mount namespace 只挂载必要目录，seccomp 过滤危险系统调用；
- 以 `nobody` 低权限用户运行，根文件系统只读；
- 判题机与 Web 前端分离，判题机不存学生隐私数据；
- Docker 方案：`--network none --memory 256m --cpus 1 --pids-limit 64 --read-only --tmpfs /tmp`；
- 编译和运行都放在沙箱内，编译器同样按不可信输入对待。

## 六、非功能需求

| 维度 | 要求 |
| --- | --- |
| 正确性 | 同一份提交多次判题结果一致；时间/内存边界明确；比对规则可解释 |
| 性能 | 30 人 × 3 题 × 5 测试点 = 450 次运行；串行按 1 秒/次约 7.5 分钟，4 并发可压到 2 分钟内 |
| 稳定性 | 单份提交异常不能中断整场；临时目录、进程、句柄必须清理干净 |
| 安全 | 见第五节；测试数据保密；判题结果不可被学生程序篡改 |
| 易用性 | 老师一条命令或一个网页完成；报告学生能看懂 |
| 可移植 | Windows 课堂可用，Linux 服务器可部署 |
| 可扩展 | 新增语言、题型、checker 不需要改核心流程 |
| 可追溯 | 保留原始提交、编译输出、每点结果，支持申诉重测 |

## 七、本仓库的实现对照

`bluebridge-judge` 是上述需求的 **P0 参考实现 + 部分 P1**，重点在“单机、批量、可信环境”。

| 模块 | 已实现 | 说明 |
| --- | --- | --- |
| 题型 | ✅ 编程题、结果填空 | — |
| 题目配置 | ✅ 时限、内存、分值、测试点分值、多答案、忽略大小写 | JSON + 完整性校验；Web 端可创建题目和测试点 |
| 测试数据 | ✅ 输入/输出文件、样例 | 暂无 zip 导入、数据加密 |
| 提交 | ✅ 名单、文件、语言识别、GBK/UTF-8 兼容、按学生/题目过滤 | 命令行用 contest.json 清单提交 |
| Web 界面 | ✅ 学生注册登录、考试/试卷选择、实时滚动成绩榜、后台串行队列；教师建题/试卷/考试/账号管理 | 教师端无登录鉴权；默认只监听本机 |
| 学生账号 | ✅ 登录名、真实姓名、密码查看/重置、登录会话、学生自助改密、教师账号详情 | 明文密码仅适合本地可信环境 |
| 试卷 / 考试 | ✅ 组卷、多套试卷、开始/结束、时长、按考试隔离成绩、实时排名开关、全员榜、结束快照 | 无考试归档/补时 |
| 编译 | ✅ g++/gcc/javac/py_compile、固定参数、CE 原文、编译超时 | 暂无编译缓存 |
| 运行 | ✅ 独立目录、时限、内存、输出上限、进程树清理、崩溃弹窗抑制 | Windows 作业对象；Linux rlimit 版较简单 |
| 隔离 | ⚠️ 工作目录隔离 + 禁止子进程 | 无文件系统/网络隔离，不能防恶意代码 |
| 比对 | ✅ token/行/精确/浮点/自定义 checker、错误定位 | — |
| 评分 | ✅ 测试点独立计分、部分分、总分 | 暂无子任务 |
| 结果 | ✅ 8 种状态、每点详情、编译输出、JSON/CSV | 暂无审计日志 |
| 报告 | ✅ 控制台、JSON、CSV、HTML 矩阵与明细、题目统计 | 暂无 PDF/图表 |
| 比赛管理 | ⚠️ | 已支持试卷/考试/时长/排名开关；无班级、封榜、申诉 |
| 防作弊 | ❌ | 建议后续加相似度与审计 |
| 多机/队列 | ❌ | 单机串行 |

**Web 端的实现方式**：

- 学生端 `/student`：注册/登录 → 选择考试 → 默认实时排名，可切换到“提交源码 / 答案”；提交绑定账号，不再填姓名；进入考试即记录为参与者；总榜包含所有进入考试的学生（未提交 0 分），各卷分榜只包含在该卷实际提交过的学生；提交页题目选择下方显示题面、输入/输出描述和醒目的输入输出样例；多套试卷时榜单支持“总榜 / 各卷分榜”切换，总榜按平均满分归一化，分榜显示原始分；
- 学生端提交结果：显示测试点结果、得分、用时、内存；测试点“说明”只显示脱敏原因（如“第 N 个数据不一致”“答案不正确”），不显示期望输出/标准答案；完整判题信息保留在后台记录和命令行报告中；
- 教师端 `/teacher`：题目、试卷、考试、学生账号四个管理页；题目支持描述（可粘贴图片）、输入描述、输出描述、多组输入输出样例，点击题目名称进入编辑页随时修改；考试支持多套试卷、开始/结束、时长、实时排名开关；**不展示**学生排名和成绩；
- 学生端与教师端导航分离：学生端不提供进入教师端的链接，教师端也不链接学生端；根路径 `/` 跳转学生端；
- 建题、建测试点、组卷、建考试、开始/结束、排名开关都有对应 HTTP 接口；
- 考试结束（手动或到点）时保存最终排名快照，教师可在考试列表查看，快照之后不再变化；
- 排名规则：AC 数降序 → 归一化总分降序 → 最早提交时间升序；多套试卷按平均满分归一化；
- 删除题目/试卷时若被引用，网页二次确认后可强制删除，并同步从相关试卷/考试中移除；
- 后台 `JudgeWorker` 用单线程队列串行评测，避免并发编译把机器打满；
- 记录持久化在 `webdata/state.json`，账号/试卷/考试在 `webdata/registry.json`，重启后保留；
- 默认监听 `127.0.0.1`，学生有账号；为方便教师查看/重置，本地版保存可查看的密码明文，教师端没有登录鉴权，定位是课堂/校内工具。

**实现上的几个关键取舍**：

1. 判题进程使用**文件重定向**而不是管道，避免输出量大时父子进程互相等待；
2. Windows 上给学生程序设置**硬内存上限（题目限制的 2 倍）**，再用峰值判断 MLE——这样既能拿到真实峰值，又不会让内存炸弹拖垮机器；
3. 编译输出中的临时路径会被替换成相对路径，老师看到的是 `main.cpp:10: error: ...`；
4. 每份提交的异常都会被捕获成 `SE`，不会让一份坏提交中断整场评测。

## 九、一句话总结

**必须有的功能是：题目与测试数据管理、多语言编译、受限运行（时间/内存/输出/进程树）、可靠的输出比对、按测试点计分、清晰的成绩报告。**

**决定这套系统“像不像蓝桥杯”的，是三个细节：填空题/编程题两种题型、按测试点给部分分、以及限时/批量评测而不是实时反馈。**

**决定这套系统“能不能长期用”的，是安全隔离和可追溯性——这两点在本仓库的 Windows 本地版里只做了基础保障，公网部署前必须补强。**
